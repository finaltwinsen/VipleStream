## v2.0.318 — Game motion vectors for VR, 144 fps static desktop, security review

<a id="en"></a>**English** · [繁體中文](#zh-tw)

This release collects everything since 2.0.285: game motion vectors for Steam Frame frame synthesis, flat-screen pacing that reaches the requested frame rate, and a full security and robustness review. **If you use the Windows or Linux desktop client 2.0.285, its self-update cannot install this version — download it by hand once** (fixed from here on).

### Assets
| File | Description |
|---|---|
| `VipleStream-Server-Setup-2.0.318.exe` | **Windows server installer (recommended for a first install)**: registers the service, adds firewall rules, installs ViGEmBus and asks once about anonymous logs |
| `VipleStream-Client-Setup-2.0.318.exe` | Windows client installer |
| `VipleStream-Client-2.0.318.zip` | Windows client (portable) |
| `VipleStream-Server-2.0.318.zip` | Windows server (portable; also used by self-update) |
| `VipleStream-Android-2.0.318.apk` | Android client (versionCode 20318, Android 9 or later) |
| `VipleStream-Client-2.0.318-linux-x64.deb` | Linux x64 client package (Ubuntu 26.04 or newer; installs to `/opt/viplestream`) |
| `VipleStream-Client-2.0.318-linux-x64.AppImage` | Linux x64 client (portable) |
| `VipleStream-Server-2.0.318-linux-x64.deb` | Linux x64 server |
| `VipleStream-SteamFrame-2.0.318.run` | **Steam Frame installer in one file** (install script plus client) |
| `VipleStream-Client-2.0.318-linux-arm64.flatpak` | Steam Frame client on its own |
| `VipleStream-SteamFrame-Install-2.0.318.sh` | Steam Frame install script on its own |
| `VipleStream-Drivers-2.0.318-windows.zip` | Windows drivers on their own (same content as in the Server zip, with a README) |

### What's new
- **VR frame synthesis with the game's own motion vectors**: the headset uses real motion vectors for its in-between frames instead of guessing from the picture, and keeps HUDs and menus from smearing. Needs the UEVR plugin built from `Sunshine/tools/uevr_mv_plugin` (not included in this release yet).
- **Headset frame synthesis is cheaper**: still areas skip the motion search (flow pass about 58% faster, about 0.25 ms less GPU per synthesized frame).
- **Flat-screen streams of a still picture now reach the requested frame rate** (for example 64 → 144 fps); delayed input work such as mouse-button release and key repeat runs on time.
- **Security**: first-time web account setup follows `origin_web_ui_allowed`; repeated wrong logins from one address are locked out for a while; if two devices wait for a PIN at the same time the PIN is refused (the message lists their addresses) instead of being applied to one of them; a limit on pending pairings per address; the host's plain-HTTP launch endpoints only accept the relay; a relay without `relay_psk` can no longer start, resume or quit apps; cover uploads checked; sensitive headers masked in logs.
- **Robustness**: the host recovers when an encoder teardown hangs or the desktop capture reports an error instead of freezing or ending the stream; less busy-waiting in the SteamVR driver and scene detection while idle; Android no longer crashes on a forged USB permission broadcast; RTSP parsing bounds and size limits.
- **Desktop client**: connection warnings are drawn on the main thread; host and app names are always shown as plain text; fewer relay and cover-art requests.
- **Anonymous logs** mask user names (also when the host runs as a service), home folders and short device names more thoroughly.

### Known limitations
- Game motion vectors need a UEVR-supported game and the plugin built by hand.
- A relay without `relay_psk` can still list apps but no longer launch them; set `relay_psk` on the host and the relay.

### Upgrade
- Windows server: run `VipleStream-Server-Setup-2.0.318.exe`, or use "Check for updates..." in the tray menu.
- Desktop clients on 2.0.285: install `VipleStream-Client-Setup-2.0.318.exe` / the `.deb` / the AppImage by hand once. Other clients update themselves.

## v2.0.318 — VR 用遊戲動態向量、2D 靜態畫面 144 fps、安全審查

[English](#en) · **繁體中文**

這版收錄 2.0.285 之後的所有改動：Steam Frame 補幀用遊戲自己的動態向量、2D 串流達到要求的幀率，以及一次完整的安全與穩健性審查。**用 2.0.285 桌面 client（Windows 或 Linux）的人，自動更新裝不了這版，請手動下載一次**（之後就正常了）。

### Asset

| `VipleStream-Drivers-2.0.318-windows.zip` | Windows 驅動程式獨立包（內容同 Server zip，附 README） |

### What's new
- **VR 補幀用遊戲自己的動態向量**：頭盔補中間幀時用遊戲給的真實動態向量，不再從畫面猜，HUD 與選單也不會被拖花。要自行從 `Sunshine/tools/uevr_mv_plugin` 建 UEVR 外掛（這版還沒附）。
- **頭盔補幀更省**：靜止區域跳過搜尋（光流 pass 約快 58%，每張補幀少約 0.25 ms GPU）。
- **2D 串流的靜態畫面達到要求的幀率**（例如 64 → 144 fps）；滑鼠放開、按鍵連發等延遲動作準時執行。
- **安全**：第一次設定網頁帳密依 `origin_web_ui_allowed`；同一位址連續登入錯誤會暫時鎖住；同時有兩台裝置在等 PIN 時拒絕（訊息列出它們的位址），不再套到其中一台；每個位址的待配對數有上限；主機的 HTTP 啟動端點只接受中繼；沒設 `relay_psk` 的中繼不能再開始、接續或結束 App；封面上傳加檢查；log 遮掉敏感標頭。
- **穩健性**：編碼器拆除卡住、桌面擷取出錯時主機會恢復，不再凍結或結束串流；SteamVR driver 與場景偵測閒置時不再空轉；Android 不再因偽造的 USB 權限廣播當掉；RTSP 解析加界限與大小上限。
- **桌面 client**：連線警告改在主執行緒繪製；主機與 App 名稱一律以純文字顯示；relay 與封面請求變少。
- **匿名 log** 更徹底遮掉使用者名稱（主機以服務執行時也一樣）、家目錄與短的裝置名稱。

### 已知限制
- 遊戲動態向量需要 UEVR 支援的遊戲，外掛要自己建。
- 沒設 `relay_psk` 的中繼仍可列出 App，但不能啟動；請在主機與中繼都設定 `relay_psk`。

### Upgrade
- Windows server：執行 `VipleStream-Server-Setup-2.0.318.exe`，或在系統匣選單用「Check for updates...」。
- 2.0.285 的桌面 client：手動安裝一次 `VipleStream-Client-Setup-2.0.318.exe`／`.deb`／AppImage。其他 client 會自動更新。
